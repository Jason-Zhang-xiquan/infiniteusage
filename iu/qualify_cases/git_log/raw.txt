    fix(groq): clamp reasoning_effort to low/medium/high (#1480)
    
    Groq rejects any reasoning_effort outside its low/medium/high enum with a 400
    ("reasoning_effort must be one of low, medium, or high", seen on
    openai/gpt-oss-120b). A client sending 'none' or 'minimal' therefore lost the
    platform for that request: the failure classifies as a provider bad request, so
    the router fell through to the next candidate instead of answering from Groq.
    
    The policy table already models this for GitHub Models, whose enum is the same
    three values, so Groq now uses the same clamp rather than forwarding the value
    verbatim. Clamping instead of dropping keeps the knob on the wire, at the
    weakest setting Groq accepts.
    
    Test updated in the same file: the per-platform clamping case now covers groq,
    and the "platform without a restriction" example moves to cerebras.
