# 能不能把小任务、子任务、重复的体力活都交给免费额度？（2026-10-17）

原始调研：[raw/04_free_llm_apis.md](raw/04_free_llm_apis.md)（免费 API）、[raw/05_free_agents.md](raw/05_free_agents.md)（免费 agent）。
免费额度每周都在变，下面的数字都要在接入时实测一次。

## 结论

**能，但只适合「一次调用就能做完」或「做完很容易检查」的活。** 整个开发流程不能全换成免费的。

- 所有合规的免费池加起来，持续每天大约能接 **1000 次单次调用**。一个重度开发者每天的摘要、解释、草稿类子任务，这个量够用。
- 一个完整的 agent 任务要 20~100 次调用，所以免费池**替代不了 Claude Code 主线程**，只能当它的「外包工人」。
- Claude Code 继续当包工头：拆任务、做决定、验收。外包出去的活，Claude 只看结果摘要或 diff。

## 你点名的几个

| 产品 | 能不能当外包工人 | 原因 |
|---|---|---|
| **Devin** | ❌ | 免费版只有桌面编辑器（原 Windsurf），云端 agent 和 API 都要付费，脚本调不动 |

| Qwen Code | ❌ | 免费 OAuth 在 2026-04-15 停了 |
| iFlow / Roo Code | ❌ | 已经关停 |
| Amp / Kiro / Cursor / Trae / Factory | ❌ | 免费版只能交互使用，或者根本没有免费版 |

## 可用的免费工人（按推荐顺序）

| 工人 | 免费额度 | 会不会拿你的代码训练 | 适合干什么 |
|---|---|---|---|
| **OpenCode + Zen 免费模型** | 按 IP 限速，具体数没公开 | 指定的 3 个模型不训练 | 带工具循环的小任务：批量改、写测试、搜代码并总结 |

| **Jules**（Google，云端 agent） | 15 个任务/天，异步执行 | 私有 repo 不训练（2025 年的条款） | 写清楚的小工单（补测试、升依赖），交回 PR |

| DeepSeek V4-Flash（**付费**） | 约 $0.004/次，1000 次约 $4 | 数据存在中国 | 免费池都满时的保底；质量接近 Sonnet 4.6 |

## 哪些能外包，哪些不能

判断标准：**检查结果的成本远小于自己做的成本**，才外包。

| 外包给免费工人 | 留在 Claude / Codex |
|---|---|
| 读大文件、长日志、测试输出，只回结论 | 架构和设计决定 |
| 搜代码，回答「X 在哪里、怎么调用的」 | 跨多个文件、有隐含约束的重构 |
| 写测试草稿、样板代码、文档、commit message | 难查的 bug |
| 翻译、正则、SQL、数据转换脚本 | 安全、并发、权限相关的代码 |
| 有测试兜底的机械改动（重命名、API 迁移） | 最终评审和合并 |
| 第一轮代码评审，列出疑点让 Claude 筛 | 需要你的上下文和偏好的活 |

## 为什么能省得多：双重收益

你过去 7 天的日志显示，Claude 用量的 91% 发生在主对话里，子 agent 只占 9%。工具调用里 Bash 有 1.17 万次、Read 有 2674 次，全是最贵的模型亲手在读文件、看命令输出。

外包之后有两层收益：

1. 这些读和总结花的是免费 token
2. 主对话只收到几百字的结论，**上下文涨得慢，后面每一轮都少重读一截**。前面算过，你约 70% 的用量是重读上下文，所以这一层可能比第一层还大

具体能省多少，要用 A/B 测，不能拍脑袋。

## 免费 API 的统一入口：用现成的路由器，不自己写（详见 [raw/07_free_api_routers.md](raw/07_free_api_routers.md)）

**首选 [FreeLLMAPI](https://github.com/tashfeenahmed/freellmapi)**（3.6 万星，MIT）：

- 预置了 34 家免费 API，对外只有一个 `/v1` 入口，兼容 OpenAI 和 Anthropic 两种格式
- 按每个 key 记录每分钟和每天的额度，遇到 429 自动冷却、换下一家
- 免费模型列表会自己更新（免费版晚 30 天）

要注意的：

- 它每天两次从官网拉一份签名的模型清单。README 写明清单服务器看不到提示词和 key，但这毕竟是一个对外连接
- 每家只放 1 个 key，不要用它的「一家多 key」功能，那是在绕限速
- 私有项目要关掉会训练的提供商

**备选 LiteLLM**（6.1 万星，最成熟）：

- 不连任何外部服务，只做故障转移
- 不记录每日额度，免费模型列表也要自己维护
- 2026-03 PyPI 上有两个版本被投毒，安装时要锁定版本

**不用**：gpt4free（逆向网页接口）、9router / CLIProxyAPI（转发订阅登录态、多号轮换），以及各种托管的中转站（它们能看到你的 key 和代码）。

部署位置：Mac mini（一直开着），Windows 通过 Tailscale 访问。下面的 `iu ask` / `iu sum` 都只调这一个入口。

## 方案：`iu` 加一个「外包工人」模块

Claude Code 不换后端（订阅 OAuth 不能接代理），只是多了几个它可以调用的命令。写进 CLAUDE.md 或做成 skill，让它知道什么时候该用：

| 命令 | 作用 | 后端 |
|---|---|---|
| `iu ask "问题" 文件...` | 单次问答：读文件，回答问题或写草稿 | 免费 API，按敏感度路由，遇到 429 自动换下一家 |
| `iu sum -- npm test` | 跑命令，只把失败和关键信息的摘要交给 Claude，不让几千行原始输出进上下文 | 同上 |
| `iu task "工单"` | 在 git worktree 里让 OpenCode 用免费模型做一个小任务，跑测试，交回 diff 和测试结果 | OpenCode Zen |

### 必须有的护栏

- **按项目分敏感度**：私有项目只走不训练的（Groq、OpenRouter 关训练、OpenCode 的 3 个零留存模型）；开源或不敏感的才可以用 Gemini、NIM
- **调用前去掉密钥**：自动过滤 `.env`、key、token 一类内容
- **只用官方渠道**，每个服务一个账号：不轮换多账号，不用 OAuth 代理，不绕限速
- **验收**：`iu task` 必须测试通过，Claude 只看 diff；通过率太低的任务类型自动退回 Claude 自己做
- **记账**：每次外包都记下省了多少 token、是否被采纳，这些数据进账本

## 怎么验证不伤结果

用 TODO 里的固定任务集做 A/B：同一个任务，「Claude 自己做」和「Claude 加外包」各跑 3 次，比较三样：

1. 付费额度用了多少（账本）
2. 结果质量：测试是否通过、你的人工评分、返工次数
3. 总耗时：免费模型有限速，可能会变慢

只有付费用量明显下降、质量和耗时不变差的任务类型，才默认外包。
