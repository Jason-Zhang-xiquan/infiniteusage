# 阶段 B v2 设计：长会话任务 A/B（等批准）

为什么改设计（[phase_A_results.md](phase_A_results.md) 之后试跑了一对）：

- Sonnet 跑测试时自己会加 `| tail -N`，hook 碰不到，A 组和 B 组的花费几乎一样（74.6K vs 76.8K 等效 token）
- 任务太短：7 轮就做完，新增上下文约 2.4 万 token。你真实会话平均每次请求带 **45 万 token**，大头是长会话里反复读文件、搜索

所以 v2 改成**长会话任务**，同时测三个杠杆：交接文件 + 新会话、外包 hook、Codex 推理强度。

## 1. 任务：「冲刺」（长会话）

仍然在 FreeLLMAPI（公开的 MIT 开源项目）的临时副本里跑，只在 Mac 上跑，不碰正在运行的服务。

每个冲刺 = **一次注入 4 个 bug + 回答 2 个查代码的问题**。bug 用已经生成好的 12 个变异，分成 3 组，每组 4 个不同文件、错误类型混合：

| S2 | think-tags.ts:121 `===`→`!==`；url-guard.ts:59 `===`→`!==`；provider-size-parser.ts:33 常量 2→3；log-redaction.ts:42 常量 9→10 | 模型清单多久同步一次？（12 小时，catalog-sync.ts:56）Kilo 匿名线路每个 IP 限多少？（每小时 200 次，providers/index.ts:268） |
| S3 | tool-args.ts:50 `===`→`!==`；tool-call-rescue.ts:68 `===`→`!==`；sampling-params.ts:58 删掉 `.trim()`；served-model.ts:31 删掉 `.toLowerCase()` | 怎么单独覆盖某个提供商的超时，设成 0 会怎样？（`PROVIDER_TIMEOUT_<平台>`，0 = 不限时，provider-timeout.ts:4）首次设置码由哪个函数、在哪个文件生成？（`generateSetupCode`，lib/setup-code.ts） |

- 两项都满足才算成功

## 2. 分组

### Claude Code（Sonnet，无头 `claude -p`，可以马上跑）

| 组 | 做法 |
|---|---|
| **C0 基线** | 一个会话做完全部：`完成 TASK.md 里的工作` |
| **C1 交接 + 新会话** | 由运行器强制拆分。每个会话只做**一项**（修一个 bug，或者答问题），然后写 `HANDOFF.md`（做完了什么、带文件:行的发现、还剩什么），结束。下一个会话是全新上下文，先读 HANDOFF.md 和 TASK.md 再接着做。最多 7 个会话，直到它回复「ALL DONE」 |
| **C2 外包 hook v2** | 基线 + iu hook。v2 比阶段 A 多管一类命令：结尾是 `\| tail -N` / `\| head -N` 的命令，改成「完整输出交给免费模型压缩」，提示里写明 agent 原本想看最后 N 行；`\| grep` 这种精确过滤照旧不管 |

每组 × 3 个冲刺 × 2 次重复 = **18 次运行**。同一冲刺同一次重复的三组同时开跑，配对比较。

### Codex（**10-22 17:30 你的周额度重置后**才能跑）

| 组 | 做法 |
|---|---|
| **X-ultra** | `codex exec -m gpt-6.1-sol -c model_reasoning_effort="ultra"`（你 64% 的 Codex 用量跑在 ultra） |
| **X-high** | 同上，只是 `model_reasoning_effort="high"` |

3 个冲刺 × 2 组 × 1 次 = **6 次运行**；结论不清楚的话，再问你要不要加。沙箱用 `-s workspace-write`，在临时目录里运行，不用跳过沙箱的危险参数。

## 3. 量什么

| 指标 | 怎么量 |
|---|---|
| 成功率 | 上面的自动评分 |
| **付费用量** | Claude：逐条回复的 usage 去重相加，算等效 token，也记 Claude Code 报的 API 等价花费。C1 组把所有会话加起来。Codex：rollout 日志里的 token，以及**官方周额度 % 的前后变化**（一次运行约 1~2%，按组汇总看） |
| 耗时、轮数、会话数 | 运行器记录 |
| 副作用 | 重复跑同一条命令的次数；回头读原始输出文件的次数；C1 每个新会话开头重新熟悉代码花的 token；C2 的改写次数和兜底次数 |

## 4. 什么算有效（事先定好，跑完不改）

| 杠杆 | 推荐启用的条件 |
|---|---|
| C1 交接 + 新会话 | 付费用量中位数 **降 ≥ 15%**，成功率不低于基线（最多少 1 次），耗时增加 ≤ 30% |
| C2 外包 hook | 付费用量中位数 **降 ≥ 10%**，成功率同上，耗时增加 ≤ 30% |
| Codex high vs ultra | 额度 % 或付费用量 **降 ≥ 20%**，成功率不低于 ultra |

每组只有 6 次（Claude）或 3 次（Codex）运行，样本小，是**试点**。报告会给出每个冲刺各自的结果和区间，结论只说「方向是否明确」，不夸大。

## 5. 花费上限

- **Claude**：先单独跑 1 次 C0 基线，量出一次冲刺的实际花费。按 18 次外推，**超过一周 Claude 用量的 4% 就停下来问你**，否则继续。预估每次约 $1~2（API 等价），18 次约 $20~35，大约是一周用量的 1~2%
- **Codex**：6 次 × 每次约 1~2% ≈ **一周 Codex 额度的 6~12%**，10-22 重置后跑。这部分单独确认（见最后）
- 免费模型：只用 FreeLLMAPI 现有的免 key 线路；跑的都是公开代码

## 6. 运行前的准备（不花额度）

1. hook v2：支持 `| tail -N` / `| head -N`，补单元测试
2. 运行器 v2：支持冲刺任务、C1 的多会话循环、Codex 运行和额度 % 记录
3. 用假的 agent（直接执行修复补丁）验证评分器：4 个 bug 都修好算成功，少修一个算失败

## 7. 不在这次范围

- 用免费模型替代 Read（读文件）：改文件必须看原文，风险大，等交接的结果出来再说
- 那 37% 没解释清楚的上下文
- 私有项目：全程只用公开仓库
