# 免费外包实测记录

## 2026-10-18：FreeLLMAPI + `iu ask` / `iu sum`

当时只配了两家免 key 的提供商：Kilo、OVH。

### 路由和故障转移

| 测试 | 结果 |
|---|---|
| `kilo-auto` 重试 | ✅ 6.6 秒（昨晚的 60 秒超时是临时的） |
| 关掉思考 `reasoning_effort: "none"` | ✅ 2.4 秒 → **0.8 秒**，输出 49 → **21 token**，回答没变差 |
| 指定单个 OVH 模型连发 | ❌ 第 3 次 429：OVH 匿名线路每个模型每分钟只能调 2 次，而且指定了单个模型就没有别家可换 |
| `auto` 连发 6 次 | ✅ 6/6 成功，自动在 OVH、Kilo 的 5 个模型间轮换，1~8 秒 |

问题：`auto` 每次挑的模型不同，质量参差（有一次答非所问）。要在后台配一条只放强模型的「编程」链，用 `--model auto:<链名>` 调用。

### `iu ask`：读代码回答问题

问题：「这个解析器怎么避免同一条 Codex 回复被重复计数？旧日志没有 token_usage_record 时怎么办？」，给的文件是 `iu/codex.py`。

- ✅ 4 条要点全对，引用的行号 74、86~88、93~98 和实际代码一致
- 免费模型 `ovh/Qwen3.8-27B`，输入 1740 / 输出 237 token，4.6 秒
- Windows 上隧道断了，`iu` 自动重连成功

### `iu sum`：压缩命令输出

**用例 1：账本报告（已经很精简的输出）**：3917 → 约 2000 字符，压缩比低。模型还编了一个耗时（0.2 秒，实际 0.5 秒）。
→ 修复：命令、退出码、耗时由脚本自己打印，提示词禁止模型复述，也禁止写输出里没有的数字。
→ 结论：本来就精简的输出不值得外包，`iu sum` 是给又长又杂的输出用的。

**用例 2：303 个测试、其中 3 个失败、verbose 模式**（模拟真实测试日志）

免费模型 `ovh/Qwen3.8-27B`，输入约 7300 token，8~12 秒。原始输出另存在 `~/.infiniteusage/raw/`，Claude 需要时可以去查。

**省多少**：2 万字符约等于 5~7 千 token。不外包时，这些全部进入 Claude 的上下文，**之后每一轮都要重读一遍**；外包后只进约 400 token。会话越长省得越多，具体比例要在真实会话里做 A/B 才能确定。
