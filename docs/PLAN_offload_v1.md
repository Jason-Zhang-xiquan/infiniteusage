# 执行计划 v1：把长工具输出外包给免费模型（等批准）

依据：[docs/benchmark_2026-10-18.md](benchmark_2026-10-18.md)。
原则：**不降效率和结果**。每一阶段都有通过门槛，没过就停，不进入下一阶段。
三个阶段分开批准：A 不花额度、不改全局配置；B 会花一点 Claude 额度；C 改你的全局配置。

## 阶段 A：准备和小测（不花 Claude 额度，不碰全局配置）

| # | 做什么 | 改动的文件 | 怎么算完成 |
|---|---|---|---|
| A1 | `iu sum` 加兜底：免费模型失败、限流或超过 30 秒时，自动改用确定性过滤（det，基准 2 里 88% 命中、0 编造），**永远不卡住 agent** | `iu/offload.py`（把 `bench/run_bench.py` 里的 det 搬进来） | 断开 FreeLLMAPI 再跑 `iu sum`，能拿到 det 结果，退出码和原命令一致 |
| A2 | 写 hook 处理程序 `iu hook-pre`：读 Claude Code 传来的 PreToolUse JSON。只有同时满足下面 4 条才改写命令，否则原样放行：<br>① 工具是 Bash<br>② 命令命中白名单（测试、构建、lint、install、git log/diff/show、rg/grep/find）<br>③ 项目在试点名单 `~/.infiniteusage/pilot_projects.txt` 里<br>④ 项目没有 `.iu-private` 标记<br>改写方式：`iu sum --goal "<Bash 的 description>" -- <原命令>` | `iu/hook.py`、`iu/cli.py` | 单元测试：白名单内的命令被改写；白名单外的原样放行；hook 出错时也原样放行 |
| A3 | Codex 额度权重校准：用日志里每次请求带的官方「已用 %」，回归出缓存读、新输入、输出各占多少额度。这样就知道「降 effort」到底能省多少 | `bench/calibrate_codex.py` | 输出各类 token 的权重，以及留出数据上的预测误差 |
| A4 | 小测 hook（spike）：只在临时项目的 `.claude/settings.local.json` 里启用，不碰全局配置。用 `claude -p --model haiku` 跑 3~5 个小命令，核实 4 件事：<br>① `updatedInput` 是否生效<br>② 改写后是否还会弹权限确认（**不能**为了改写而自动放行原本需要确认的命令）<br>③ 退出码是否保留<br>④ 你在界面上能不能看到被改写了 | 临时目录，用完删掉 | 4 个问题都有实测答案，写进文档 |

A4 会用一点 Claude 额度：Haiku，几千 token，可以忽略。

**A 的门槛**：A4 证明 hook 能改写命令、不会绕过权限确认、退出码正确。任何一条不满足就停下，回来找你。

## 阶段 B：真实任务 A/B（会花一点 Claude 额度）

| # | 做什么 |
|---|---|
| B1 | 任务集：**12 个任务，只用公开开源仓库**（FreeLLMAPI 的临时副本，再加 1~2 个公开仓库），先注入 bug，用隐藏测试判对错。任务挑会产生大量命令输出的那种：修失败的测试、修类型错误、在大仓库里找配置并修改等 |
| B2 | 在 Mac 上用 `claude -p --model sonnet` 无头运行。A 组不开 hook，B 组开 hook，各 3 次，共 **72 次**。每次在独立的 worktree 里跑，互不干扰 |
| B3 | 用账本记录每次的付费等效 token、轮数、耗时，以及「看完摘要又回头读原始输出或重跑命令」的次数；用隐藏测试判定任务成功率 |
| B4 | 配对比较（Wilcoxon 检验 + 自助法置信区间），写报告 |

**额度估算**：每次约 0.2~0.4M 等效 token，72 次约 15~30M。你一周 Claude 用量约 760M，这次大约占 **2~4%**。用 Sonnet 而不是 Opus，就是为了省额度。

**B 的门槛（三条都满足才算通过）**：
1. 付费 token 中位数下降 ≥ 10%
2. 任务成功数最多少 1 个（12 个里）
3. 耗时增加不超过 25%

只有 12 个任务，统计功效有限，报告里会附置信区间，不夸大结论。

## 阶段 C：正式启用（每一步改全局配置前都单独问你）

| # | 做什么 |
|---|---|
| C1 | 你来定哪些项目算私有（加 `.iu-private`），哪些进试点名单 |
| C2 | 写进 `~/.claude/settings.json` 的 hooks（先备份），只对试点项目生效。**hook 命令必须以 `\|\| true` 结尾**（阶段 A 发现：hook 坏掉时会拦下所有 Bash 命令）；先在 FreeLLMAPI 配一条固定的强模型链，不用开放的 `auto`；你现有的「自动允许」规则不再匹配改写后的命令，要定是给外包命令加一条允许规则，还是继续靠 auto 模式的判断 |
| C3 | Codex：`~/.codex/hooks.json` 用同样的方式改写（Codex 的 PreToolUse 也支持 `updatedInput`） |
| C4 | Mac：同步 `iu` 和 hook；FreeLLMAPI 用 launchd 开机自启 |
| C5 | 你加 Groq key 后，配一条只走 Groq 的「私有」链（Groq 默认不留存数据），私有项目只走这条，用之前先跑一遍基准 2 |
| C6 | 账本加一节「外包」：每周外包了多少、估算省了多少、兜底用了几次。效果不如预期就关掉 |

**回滚**：删掉 settings.json 里那一段 hook，或者删掉试点名单里的项目。随时可撤，不影响其他功能。
