# 大杠杆研究结果（2026-10-18 夜 → 10-19）

数据：`bench/results/night.jsonl`（96 次）+ `night_s3fix.jsonl`（3 次）。Mac 上跑，公开仓库 FreeLLMAPI 的冲刺任务（每次修 4 个 bug + 答 2 个问题），每组 12~13 次，3 个冲刺都覆盖。
花费是 Claude Code 报的 **API 等价价格**（`total_cost_usd`）。区间用自助法算（冲刺内重抽，3 个冲刺等权平均）。

## ⚠️ 超支说明

计划今晚每组只跑 1 次（约 27 次，$16）。缩规模时我杀了原来那条队列的父进程，但 bash 要等当前子进程跑完才处理信号，所以**原来的 72 次也跑了，和新的 24 次同时进行**。合计 99 次，**$52**，约为批准额度的 3 倍。两个会话同时跑，可用内存一直在 89~91%，没有触发内存中止。

## 结论

1. **主线程用 Opus 比 Sonnet 省一半（-49%，区间 -54% ~ -40%），成功率一样（12/12），还更快。** Opus 只要一半的轮数，上下文也只有一半大。
   - 按 token 量算，Opus 用的 token 约为 Sonnet 的三分之一；就算订阅额度里 Opus 按更高的权重扣，大概率还是更省（**这一点还要用官方额度 % 核实**）
   - 你 85% 的 Claude 用量本来就在 Opus 上，**这个选择是对的**。「换成 Sonnet 省钱」是错觉
2. **Haiku** 比 Sonnet 便宜（-36%），但比 Opus 贵，而且有 1 次失败、更慢。**不推荐**
3. **提前压缩（100K 窗口）：不推荐。** 在 Sonnet 上反而 **+19%**（压缩本身要花钱：重写上下文、重建缓存）；在 Opus 上几乎不触发，没有变化。注意：这里的任务上下文只有 4~8 万；在你真实的 45 万 token 长会话里，结果可能不同，**还没测**
4. **Opus 降推理强度（medium）：不推荐。** +6%，不省钱
5. **探索闸门（搜代码交给免费 agent）：没有可靠的收益。** Sonnet 上 -11%，但区间跨过 0；Opus 上 -2%。免费 agent 本身答得准（每次运行调用 1~10 次，99 次运行里只有 2 处引用没核实），只是这类任务里搜代码本来就不贵
6. 之前通过的**外包长输出 hook**只在 Sonnet 上测过（-20%）。**还没在 Opus 上测**，这是下一步

## 对产品的意义

到目前为止，有证据的只有两条：

- **用 Opus 当主模型**：-49%，这次的结果
- **外包长输出**：Sonnet 上 -20%，Opus 上待测

测过但不收录的：交接 + 新会话、ponytail、调小输出上限、降推理强度、提前压缩、探索闸门（目前证据不足）、Haiku 主线程。

## 局限

- 都是公开仓库里的冲刺任务，上下文只有 4~8 万 token；你真实会话平均 45 万，长会话的结论可能不同
- 花费是 API 等价价格，不是订阅额度 %
- 两条队列同时跑，机器负载比计划高；不过每组的条件是一样的（交错着跑）
