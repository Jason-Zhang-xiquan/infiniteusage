# 「失忆鹈鹕」视频脚本（2026-10-24）

素材都在 `bench/results/pelican/video/`：
- `story.html`：竖屏 1080×1920 动画，浏览器打开就自动播放，约 20 秒。录屏就是成片主体。空格键重播，地址后面加 `?speed=0.5` 放慢
- `timeline.png`：三条上下文曲线（红线一路涨到 19 万；黄、绿两条锯齿，每个圆点是一次压缩）
- `grid.png`：三只鹈鹕并排，带分数和用量
- 单张图：`../claude_hard_A_2.png`（不压缩）、`../claude_hard_C_2.png`（记笔记）

## 一句话钩子

> 我让 Claude 中途「压缩记忆」7 次，最后让它画一只鹈鹕骑自行车。它说：「我们之前约定过什么？」

## 结构（约 45~60 秒）

| 时间 | 画面 | 口播 / 字幕 |
|---|---|---|
| 0~3 秒 | `story.html` 开头，标题「失忆鹈鹕」 | 「AI 的记忆会被压缩。压缩 7 次之后，它还记得你说过的话吗？」 |
| 3~8 秒 | 快速闪过 6 段规格（围巾颜色、路牌 IU-42→43→45→46、7 只鸟、瓢虫……） | 「我先跟它定了 16 条细节，中途还改了好几次，然后让它去干一堆别的活」 |
| 8~20 秒 | 三根柱子一起涨；黄绿两根每次「🧠 压缩」就掉下去 | 「左边不压缩，记忆一直涨。中间每涨到一定程度就压缩一次，右边压缩的同时让它记笔记」 |
| 20~28 秒 | 结尾画面：左边一只完美的鹈鹕 16/16 | 「不压缩：16 条全对」 |
| 28~36 秒 | 中间那张卡：它的原话 | 「压缩 7 次：它说『我没找到我们之前约定的规格，能贴一下吗？』一条都不记得了」 |
| 36~44 秒 | 右边 12/16 | 「记笔记那组：救回来 12 条，只丢了 4 个小细节」 |
| 44~55 秒 | 大字「压缩太狠，AI 直接失忆」，再切 `timeline.png` | 「而且压缩 7 次的那组，用量一点没省，还多了 2%。压缩不是越狠越好」 |
| 结尾 | 项目名 / 链接 | 「我在做的 InfiniteUsage，就是找那个刚刚好的点：省 token，但不让它失忆」 |

## 必须说清楚的（不然会被挑刺）

- 模型是 **Claude Sonnet**，每组只跑了 **1 次**，属于演示，不是严格统计
- 为了省钱，压缩点**缩小了**：每到约 6.7 万 token 就压缩一次。正常 Claude Code 要到约 96.7 万才压缩，InfiniteUsage 设在约 30 万。所以这个视频展示的是「压缩太频繁」的后果，**不是 InfiniteUsage 实际设置的效果**
- 「用量」是等效 token：缓存读按 0.1 倍算、输出按 5 倍算
- 16 条细节是程序按 SVG 代码自动判的，不是人眼打分
