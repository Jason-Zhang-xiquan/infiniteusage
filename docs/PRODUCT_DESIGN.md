# InfiniteUsage 产品设计：任何 agent 都能装的「同等结果、更低成本」工具包（草案，等批准）

## 0. 目标和两条硬要求

**目标**：一个 AI 能自己下载、安装、使用的 skill + 代码库。装上以后，Claude Code、Codex、Cursor、WorkBuddy 这类 agent 产出的结果质量不变，付费额度花得少很多。

**可解释性**：每一处省钱都能说清楚是哪个机制、省在哪、凭什么没降质量。
- 每次改写都留痕，输出开头注明用了哪个模型，原始输出存成文件
- 有一份「这次会话的 token 花在哪」的报告
- 每个机制都附上证据：测试数据和复现脚本

**强度**：
- 永不卡住 agent：出错原样放行，免费模型失败就改用规则过滤
- 不编造：发现编造的位置就丢掉摘要，关键报错原样补回
- 不越权：不替用户放行任何命令
- 不泄露：私有项目不外包，调用前过滤密钥
- **只收录实测有效的机制**；测了没用的机制写进证据文档，不装

## 2. 架构：五层，每层可以单独用

```
┌─ 安装层  iu install --agent claude-code|codex|cursor|workbuddy [--dry-run] / iu uninstall
│          先备份、能撤回；AI 照着 INSTALL.md 就能自己装
├─ 接入层  每种 agent 一个适配器：拦截长输出命令 → iu sum
│          Claude Code：PreToolUse hook（已实测）  Codex：PreToolUse hook（文档支持，待实测）
│          Cursor、WorkBuddy/CodeBuddy：待查有没有 hook；没有就退到规则文件（不强制，效果弱，会标明）
├─ 外包层  iu sum / iu ask：密钥过滤 → 按任务类型取路由链 → 免费模型 → 护栏 → 规则兜底
│          后端：任何 OpenAI 兼容地址（FreeLLMAPI、LiteLLM、自己的 key 都行）；私有项目只走不留存数据的线路
├─ 画像层  iu profile：每周自动用固定语料给免费模型打分 → 生成路由表；模型变差就自动降级
└─ 证据层  iu report：每个会话的 token 花在哪、外包省了多少、兜底和失败几次
           iu bench：在你自己的机器、你自己的任务上复现 A/B（离线质量基准 + 真实任务配对）
```

- 纯 Python 标准库，Windows、Mac、Linux 都能跑，Python 3.9 以上
- 代码库里不含任何个人路径、key 或账号
- 证据文件 `EVIDENCE.md`：每个机制一节，写清楚测了什么、结果如何、复现命令、局限

## 3. 对 Claude Code 的打包形式

做成 **Claude Code 插件**（插件里包含 hooks、skill、命令）：

- 安装：`/plugin install`，或者让 agent 读 `INSTALL.md` 跑 `iu install`
- hook 命令必须带 `|| true`（阶段 A 发现：hook 坏掉会拦下所有 Bash 命令）
- 附带一个 skill，教 agent 三件事：什么时候用 `iu ask` 外包读文件、看到摘要以后怎么按行号读原始输出、不要重跑命令

Codex：`~/.codex/hooks.json` + AGENTS.md 片段。

Cursor、WorkBuddy：先查清楚各自有什么接入点，再定形式。

## 4. 要做到「便宜很多」，还缺的杠杆（按潜在收益排序，都要先测再收录）

根据基准 1（你的真实日志），Claude 上下文里大头是：
- 助手的工具调用参数：18.6%
- 读文件：18.1%
- 搜索：7.3%
- **没解释清楚的部分：37%**

| 杠杆 | 思路 | 潜在收益 | 风险 |
|---|---|---|---|
| A. **整块子任务外包给免费 agent** | 把「找出 X 在哪、怎么工作」这类探索交给 OpenCode（免费模型）或带免费模型的子 agent，只把结论交回 | 读文件 + 搜索约占 25% | 结论错了会误导主 agent，必须有验证 |
| B. **主线程用便宜一档的付费模型** | 你 85% 的 Claude 用量在 Opus 上；常规活交给 Sonnet 当主模型，Opus 只在规划和难题时用 | 可能是最大的一刀（模型单价差好几倍） | 质量会不会降，要 A/B |
| C. **按需读文件** | 先用免费模型定位到具体行，再按行号读，不读整个文件 | 读文件 18% 的一部分 | 改文件需要原文 |
| D. **弄清那 37%** | 很可能是完整的思考内容和截图，先测清楚再说 | 未知 | — |
| E. **观察遮蔽** | 旧的工具输出不再带着走（学术论文：-50%、质量不变） | 大 | 要查 Claude Code 能不能开 |

B 和 E 可能比外包大得多。按「只收录实测有效的」原则，每个都要过同样的 A/B 门槛。

## 5. 路线图

| 阶段 | 内容 | 花不花额度 |
|---|---|---|
| **P1 打包** | 把现有的 `iu` 整理成可发布的代码库：安装和卸载（Claude Code 先做）、插件形式、EVIDENCE.md、INSTALL.md、去掉个人路径；后端支持任意 OpenAI 兼容地址；查清楚 Cursor 和 WorkBuddy 的接入点 | 不花 |
| P2 补证据 | 补跑 S3；在真实长会话规模的任务上测外包（现在的任务上下文最多十几万，你平时是 45 万） | 少量 Claude |
| P3 大杠杆 | 依次测 B（主模型降一档）、E（观察遮蔽）、A（探索外包给免费 agent） | Claude 每项约 $10~20 |
| P4 多 agent | Codex hook 实测（10-22 之后）、WorkBuddy 和 Cursor 适配器 | Codex 少量 |
| P5 发布 | 公开仓库、CI、发布前检查（没有 key 和私人信息） | 不花 |

## 需要你定的

1. 这个方向和五层架构对不对
2. 先做 P1（打包，不花额度），还是先做 P3 里最大的杠杆（比如 B：主线程换 Sonnet）
3. 最终要不要公开发布（会影响命名、许可证和隐私检查）
